## Ideas for review

These are structural/coverage notes that don't fit the auto-generated gap list above.
Triage by Sutharsan; not acted on automatically.

- **`simulation_step` is a false positive.** The gap above comes from `nav2_bringup/params/nav2_params.yaml`
  using `controller.simulation_step`, but the opennav_docking controller actually declares
  `controller.simulation_time_step` (see `nav2_docking/opennav_docking/src/controller.cpp`), which is
  already in the schema. The bringup YAML key is stale/misspelled upstream — there is no real missing
  param here, so the gap list will keep showing "1 missing" until the gap script special-cases it.
- **`SimpleNonChargingDock` dock plugin is not represented.** `docking_server` only has
  `SimpleChargingDock` plugin params in the schema. The `SimpleNonChargingDock` plugin
  (`nav2_docking/opennav_docking/src/simple_non_charging_dock.cpp`) exposes ~20 params that share the
  same relative names as the charging dock (minus `use_battery_status`/`charging_threshold`). They can't
  be added as-is because the schema keys plugin params by bare `(node, param)` and the uniqueness tests
  (`test_node_param_uniqueness`, `test_effective_ros2_name_unique_per_node`) reject two docking plugins
  sharing a name. Supporting a second dock plugin needs a dock-instance-prefix convention for docking
  plugin params (like the `FollowPath.` prefix used for controller plugins) — a modeling decision.
